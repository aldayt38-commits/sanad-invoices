## 1. تسجيل الدخول والتخزين السحابي (المطلب الأول)

### 1.1 المطلوب
كل دَين ينضاف يُخزَّن على حساب المستخدم؛ تسجيل الخروج ثم الدخول من أي جهاز = كل شيء موجود، **إلّا إذا حذفه المستخدم نفسه**.

### 1.2 بدائل مُقيَّمة

| البديل | يعمل بلا سيرفر؟ | دخول مريح للمستخدم؟ | تكلفة | تقييم |
|---|---|---|---|---|
| **A. GitHub PAT + Secret Gist** (المختار) | ✅ نعم | ⚠️ لصق توكن (مقبول لجمهور tech + خطوات ميسّرة) | $0 | ✅ قابل للتنفيذ الآن بلا أي بنية تحتية |
| B. Firebase Email/Password + Firestore | ✅ نعم | ✅ ممتاز (إيميل+باسورد) | مجاني Spark | ⏳ يحتاج إنشاء مشروع Firebase بحسابهم — **خارطة طريق** |
| C. Supabase | ✅ | ✅ | مجاني | ⏳ مثل B |
| D. سيرفر مخصص | ❌ | ✅ | $$/شهر | ❌ يكسر نموذج Pages ويجيب تكلفة تشغيل |
| E. تخزين محلي فقط (localStorage) | ✅ | — | $0 | ❌ لا يحقق شرط «يتجاب من جهاز تاني» |
| F. خدمات لصق مجهولة | ✅ | — | $0 | ❌ مرفوض: بيانات ديون على خدمة عشوائية بلا حساب |

### 1.3 القرار: **المسار A — دخول بتوكن GitHub + نسخة سحابية خاصة (Secret Gist)**
- **الدخول:** المستخدم ينشئ توكن بصلاحية `gist` فقط → يلصقه بحقل الدخول → نتحقق عبر `/user` → يُحفظ بالجهاز.
- **التخزين:** ملف `dhimmati.json` داخل **Secret Gist** خاص (غير قابل للاكتشاف، يحتاج الحساب).
- **المزامنة:** حفظ تلقائي مؤجّل (debounce 1.2 ثانية) بعد كل تعديل + سحب كامل عند الدخول على جهاز جديد.
- **تسجيل الخروج:** مزامنة أخيرة ثم مسح محلي (أمان على الجهاز المشترك) — الجلسة تحذف، **البيانات تبقى سحابيًا**.
- **عند الدخول وفيه بيانات محلية + سحابية:** تُرفع نسخة احتياطية من المحلية `backup-local-<تاريخ>.json` ثم تتفوّق السحابية (لا ضياع صامت).

### 1.4 مخاطر مُعترف بها + تخفيفها

| الخطر | التخفيف |
|---|---|
| التوكن مكشوف بحقل الدخول | يُخزَّن محليًا فقط، **لا يُرفع لأي سيرفر غير GitHub**، نطاقه `gist` فقط + انتهاء صلاحيته اختياري (7–90 يوم) |
| Secret Gist ليس مشفّرًا (GitHub يقرأه) | مقبول لبيانات أرقام أسماء؛ **خارطة طريق: تشفير قبل الرفع بمفتاح عبارة مرور (E2EE)** |
| فقدان التوكن | يُنشأ توكن جديد → الدخول يسترجع كل شيء من السحابة |
| اعتماد على متصل خارجي (api.github.com) | بلا إنترنت يشتغل التطبيق محليًا، والمزامنة تلحّق عند العودة (`online` event) |
| توكن المستخدم بيد التطبيق | سياسة: **ممنوع تثبيته بالكود أبدًا** — اختبار `tests/smoke.mjs` يفحص عدم وجود `ghp_` بأي ملف بالمستودع |

### 1.5 مقارنة الأثر على مؤشر الجدوى
- معيار **الاحتفاظ (كان 94)** ← يتحسّن: البيانات المفقودة سبب رئيسي لترك أدوات الدفتر.
- معيار **الثقة/الخصوصية**: مخاطرة جديدة (التخزين بـ GitHub) مقابل مكسب (لا سيرفر مطوّر يرى البيانات).

## 2. التصنيفات المخصّصة (اقتراح المستخدم: «البيت، الدكان، …»)

### 2.1 التصميم
- قائمة تصنيفات يضيفها المستخدم بنفسه (افتراضيًا: **البيت، الدكان** — يُحذف ويُعدَّل من الإعدادات).
- **التصنيف على مستوى الشخص/القيد** (ليّا عليه/عليّ له) وليس على كل حركة دفعة — بساطة في العرض والفلترة، ويكفي لأن الدفعة تخصّ نفس العلاقة.
- رسم في نموذج الإضافة/التعديل (شيل اختيار + «+ جديد» لصق حرّ).
- **فلترة بالتصنيف** بصفحة الأشخاص + **سطر «أعلى تصنيف»** ببطاقة الملخص المشتركة.

### 2.2 بدائل مرفوضة
- تصنيف لكل حركة (دفعة/دين): أدقّ، لكن يُعقّد الرصيد والفلترة بلا عائد واضح للنسخة الأولى → خارطة طريق.
- تصنيفات جاهزة مفتوحة فقط: تُجبر المستخدم على تصنيفات غريبة عليه → اخترنا الحرّ.

## 3. المواعيد والتنبيهات (اقتراح المستخدم)

### 3.1 المطلوب
تحديد موعد انتهاء الدين → عند الانتهاء: «تم انتهاء الدين»؛ وإذا لسّا ما سدّد: «نسيت تسدد الدين».

### 3.2 ما نفّذناه (بدون أي سيرفر)
1. **موعد استحقاق لكل دَين** (تاريخ) بحقل الإضافة/التعديل + ورقة مستقلة من التفاصيل.
2. **حالات مرئية:** 🔴 متأخر (X يوم) · 🟡 اليوم · 🟢 باقي X يوم · ✔ مسدّد قبل/عند الموعد — بالمصفوفة الرئيسية + شريط فلترة «متأخرات».
3. **شريط المتأخرات بالرئيسية:** «⏰ X ديون متأخرة» بأسمائها بضغطة وحدة.
4. **تنبيهات متصفح (Notification API):** عند فتح التطبيق ودوريًا كل6 ساعات: لمن عليه دين متأخر → **«نسيت تسدّد دين {الاسم} ({المبلغ})؟ الموعد كان {التاريخ}»**.
5. **«تم انتهاء الدين»:** عند التسديد لشخص كان عنده موعد → يُسأل المستخدم هل يبعت إشعار «حساباتنا خلصت/تم انتهاء الدين» للطرف الآخر (واتساب/بطاقة/نسخ).
6. **تذكير الطرف الآخر:** زر 🔔 بتفاصيل المتأخر → رسالة واتساب مهذّبة فيها المبلغ والموعد + رابط.

### 3.3 حدود صريحة (أمانة فنية)
- **ما في Push حقيقي (إشعار من خلفية والتطبيق مغلق)** بلا سيرفر/خدمة Push — ده خارج نموذج Pages. الحاضر: تنبيهات والمفتوح + شريط دائم بالتطبيق + تذكير واتساب للطرف الآخر (القناة الفعلية اللي الناس بتستعملها).
- **خارطة طريق Push:** VAPID keys + سيرفر إرسال مجاني (Cloudflare Workers/OneSignal) → إشعار مجدول حتى والتطبيق مغلق.
- صلاحية الإشعار **تُطلب سياقيًا** أول ما المستخدم يحدّد موعد (لا نطلبها عند فتح التطبيق = احترام المستخدم ورفع نسبة القبول).

## 4. مميزات مقترحة من المطوّر (فوق مطالب المستخدم)

| الميزة | السبب | الأثر المتوقع |
|---|---|---|
| **تراجع عن الحذف (Undo)** | حذف دَين بالغلط = ثقة محطّمة | خفض فقدان البيانات، يساند معيار الاحتفاظ |
| **ملاحظة على كل دفعة** («دفع نقدًا/حوالة») | الدفعة الجزئية بدون سبب = جدال بعدين | وضوح السجل = استخدام أطول |
| **شريط المتأخرات + فلترة متأخرات** | الموعد بلا عرض مركزي = يُنسى | تحويل التنبيه لفعل (تذكير/تسديد) |
| **سطر «أعلى تصنيف» بالبطاقة** | المشاركة بصير أكثر فائدة وسياقًا | انتشار أدقّ («يا أهل البيت…») |
| **مزامنة تلقائية بحالة ظاهرة** (آخر مزامنة/بانتظار/خطأ) | غياب المعلومة = شك بالحساب | ثقة = استمرار |

**مرفوض باستشارة (لحد الآن):** إعلانات (تقلّث ثقة منتج مالي) · حسابات بريد+كلمة سر بلا سيرفر (غير آمن) · دفع داخل التطبيق (قيد إقليمي — مذكور بجدوى أساسية).
